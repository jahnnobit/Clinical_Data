# Part B: Clinical Trial Data Quality Review

Part of the [Clinical Trial Oversight Toolkit](../README.md). This part is run, tested and shown in the dashboard from the project root (see below).

A portfolio project that simulates the core work of a clinical data manager on public CDISC SDTM data. It runs **20 automated edit checks** on four domains (DM, AE, VS, LB), turns every finding into a **query log**, shows data quality and database-lock readiness in a **Plotly Dash dashboard**, and documents the process in a **Data Management Plan** and an **edit check specification**. To test the checks, 50 errors were deliberately injected into a copy of the data. All 50 were found, with no false positives. The checks also found 267 genuine findings in the original public data.

> **Note:** this is a portfolio project on public CDISC pilot data, not real clinical trial work. Errors were injected on purpose and query statuses are simulated.

## Dashboard

The results are shown in the "Part B: Study data quality review" tab of the shared dashboard (`dashboard/app.py` in the project root).

## What is clinical data management?

Clinical data management makes sure that the data collected in a clinical trial is complete, accurate and consistent, so that the results can be trusted and submitted to regulators. Data managers define validation rules (edit checks), send queries to trial sites about suspicious values, and confirm the data is clean before the database is locked for analysis.

## Data source

- **Package:** [`pharmaversesdtm`](https://github.com/pharmaverse/pharmaversesdtm) ([documentation](https://pharmaverse.github.io/pharmaversesdtm/)). It contains the SDTM test datasets of the CDISC pilot study (CDISCPILOT01).
- **Files used:** `dm.csv`, `ae.csv`, `vs.csv` and `lb.csv` from `inst/extdata/`, at repository commit `7ec53ea` (see `data/raw/SOURCE.md`).
- **Errors injected on purpose.** `data/raw/` holds the original files, unchanged and read-only. `data/injected/` holds a copy with **50 deliberately injected errors**; every one is listed in `data/injected/answer_key.csv`.

## How to run

Requires Python 3.14. All commands run from the project root (`clinical-trial-oversight/`).

```bash
# 1. Set up the environment (once)
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# 2. Run this part's pipeline (spec -> error injection -> edit checks -> query log)
python data_quality_review/src/run_all.py

# 3. Run the unit tests
pytest data_quality_review/tests

# 4. Start the dashboard, then open http://127.0.0.1:8050
python dashboard/app.py
```

|---|---|

## Key decisions

- **Every value is read as text.** This means a typo such as "12OO" in a numeric field reaches the checks instead of being silently converted.
- **Checks were adapted to the real data after profiling it.** For example, LB01 compares results with the original-unit normal range because the rounded standard-unit limits caused 156 false hits. Every adaptation is documented in the specification.
- **One query per problem, not per record.** One wrong visit date affects ~30 lab records but raises one query.
- **Query texts are neutral** and never suggest the "correct" value.
- **The project does not perform MedDRA coding and does not use an EDC system.** AE coding is only checked for missing coded terms.
